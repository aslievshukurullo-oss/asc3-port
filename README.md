# Assassin's Creed III (Gameloft, J2ME 240x320) → LibGDX / Android, landscape

Источник: `assassins_creed_iii_nokia_6280_en_igp_eu.jar` (MIDlet `GloftASC3`, CLDC-1.1 / MIDP-2.0, ~1 МБ, обфусцирован).
Цель: сохранить оригинальную игру (ресурсы, логику, состояния), а не писать упрощённую копию; результат — горизонтальный APK.

## Как собрать APK

1. Создайте репозиторий на GitHub, загрузите содержимое этой папки.
2. Вкладка Actions → «Build APK» → Run workflow (или просто push).
3. Скачайте артефакт `asc3-landscape-debug-apk` → установите `app-debug.apk`.

Локально: Android Studio → Open → папка проекта (нужны JDK 17, Android SDK 34).

## Формат паков (`k.a`, `k.ak`, `k.aj`)

Файл `N` (+ тома `N.1`, `N.2`…), все числа little-endian:
```
u16 total ; u16 nvol ; u16 firstIndex[nvol]
u32 offsets[n+1]   (для тома 0 сразу после заголовка; для остальных томов — с начала файла)
```
Смещения абсолютные внутри файла тома. Запись: 1 байт флага; `>=127` → тип = флаг−127 и далее LZMA-alone поток (props, dict, size…); иначе тип = флаг, данные как есть.
Типы: 0 = MIDI, 1 = MP3 (в паке 3), 2 = обычные данные.

## Формат спрайтов ASprite (класс `a`)

См. заголовок `tools/asprite.py`. Модули (bitmap/векторные примитивы) → frame-modules → frames → animation-frames → animations; палитры (форматы 0x8888/0x4444/0x1555/0x565/RGB24) и кодирование пикселей (RLE-варианты, 1/2/4/8 bpp, альфа-плоскость). Декодирование палитры 0 запечено в атлас; остальные палитры (перекраска, ключ `W[n].a(slot, пак /22)`) — TODO.
Декодировано 3977/4032 модулей; ~89% кадров отрисованы (остальные — пустые либо из векторных примитивов, TODO).

## Карта ресурсов

| Пак | Содержимое |
|---|---|
| `/0` | список MIME (`audio/midi`, `audio/mpeg`) |
| `/1` | 2 массива int (`eO`, `eP`) |
| `/2` | шрифт и общий интерфейс (`W[55]`) |
| `/3` | звук: 6 MIDI + 32 MP3 |
| `/4` | экран-заставка (`W[50]`) |
| `/5` | спрайты игрока/врагов/эффектов (50 шт., включая Коннора) |
| `/6` | PNG 36×22 |
| `/7` | интерфейс/меню |
| `/8`, `/9`, `/11` | тайлсеты уровней |
| `/12`…`/20` | данные 9 уровней (массив `cN`: пара «тайлсет, уровень») |
| `/21` | мелкие записи (скрипты?/сущности) — не разобрано |
| `/22` | таблицы перекраски палитр |
| `EN` | строки (315 шт. в секции 0) |
| `dataIGP`, `999` | рекламный модуль Gameloft IGP — в порт не нужен |

Уровни (`cN`): L0={/8,/12}, L1={/8,/13}, L2={/9,/14}, L3={—,/15}, L4={/8,/16}, L5={/11,/17}, L6={—,/18}, L7={/11,/19}, L8={/9,/20}. Каждый пак уровня — 15 записей (карта, слои, сущности; запись 2 выглядит как слой тайлов, заполненный `0xFF`). Формат — следующий шаг: читать `k.a(cN[(L<<1)+1])` и обращения к `k.am/aj` в состоянии 2/8/9 (`k.java` ~1400–1500) и в `g.java`.

## Ввод (k.ag)
Клавиша → маска: `0..9` → 1,2,4,…,512; `*`=262144; `#`=524288; ↑1024 ↓2048 ←4096 →8192; центр=16384; левый софт=32768, правый=65536; clear=131072. Реализовано в `Keys.java`. Экранные кнопки в `TouchOverlay.java` выдают те же маски.

## Автомат состояний `k.w(n)` (поле `k` = состояние, `n` = фаза)
Фазы: 0 вход, 1 обновление, 2 отрисовка, 3 выход, 4 пауза, 5 возврат. Состояния (первичная карта): 1 инициализация (таблицы, `W[56]` спрайтов), 2 заставка + загрузка языка/шрифта (`/4`,`/EN`,`/2`) → 3, 3 → 5, 4 → 6, 6 → 7, 7 крупное (150 строк, меню/игра), 8/9 загрузка тайлсетов и палитр, 13/14/16/18/21/22/26/27 меню и переходы. Подробности: `docs/states_raw.json`; игровая логика вне `w()`: классы `g` (сущности), `j`, `l` (игрок, ~7500 строк), `b` (звук), `c` (поток), `h`, `i`.

## Горизонтальный режим
Виртуальный экран 480×320. Оригинальное окно 240×320 по центру (x=120..360), по бокам панели управления: слева крестовина и `* #`, справа `OK`, цифры `1 3 5 7 9`, софт-клавиши. Режим 1 (сейчас): окно оригинала без изменений. Режим 2 (позже): расширение камеры/интерфейса на широкий экран.
